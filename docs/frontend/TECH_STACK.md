# 前端技术选型

## 目标

前端项目需要同时服务 H5、移动端和小程序场景，因此技术栈优先保证多端一致性、工程可维护性和后续接口接入效率。

## 技术栈

| 分类 | 选型 | 说明 |
| --- | --- | --- |
| 跨端框架 | uni-app | 使用 Vue 语法开发，可编译到 H5、小程序和 App。 |
| 语言 | TypeScript | 提升接口类型约束和重构可靠性。 |
| 前端框架 | Vue 3 最新稳定版 | 与用户技术栈匹配，使用组合式 API 组织业务逻辑；初始化时优先使用当前稳定版本，并以 uni-app 兼容范围为准。 |
| 构建工具 | Vite | 使用 uni-app Vue3 CLI 体系，保持构建链路简洁。 |
| UI 组件 | uni-ui 优先，必要时评估 uView Plus | 优先使用官方跨端组件，降低平台差异风险。 |
| 样式 | SCSS + rpx | 以移动端优先，兼容小程序；暂不引入 Tailwind/shadcn。 |
| 状态管理 | Pinia | 管理用户偏好、解析历史、跨页面共享状态。 |
| 请求封装 | uni.request | 统一封装 baseURL、超时、错误结构和平台差异。 |
| 本地存储 | uni.setStorage / uni.getStorage | 保存解析历史和轻量配置。 |

## 不采用 React Web 技术栈的原因

- `Vite + React + shadcn/ui` 更适合浏览器 Web 应用，不能直接运行在小程序环境。
- `shadcn/ui` 依赖 DOM 与 Radix 组件体系，不适合作为小程序 UI 基础。
- 若先做 React Web，后续改小程序会产生明显迁移成本。

## UI 原则

- 移动端优先，PC/H5 做增强布局。
- 保持工具型产品风格，强调输入、解析、结果展示和复制/下载操作效率。
- 避免复杂视觉装饰，优先清晰的信息层级和稳定的跨端表现。
- 可复用组件只在真实重复出现后抽象，避免提前设计过多组件。

## Vue 版本策略

- 新建项目时优先使用 Vue 3 最新稳定版，不使用 Vue 2 或兼容模式。
- 依赖版本以 `package.json` 锁定，避免团队环境安装到不一致版本。
- 不追随 `alpha`、`beta`、`rc` 或 edge 版本，除非后续明确需要验证某个新能力。
- 若 uni-app 依赖链对 Vue 小版本有兼容约束，以 uni-app 官方支持版本为准。

## Vue 3 新特性使用边界

- 优先使用 `<script setup>` 和组合式 API。
- 可以使用 Vue 3.5+ 的响应式 props 解构能力，减少 `toRefs(props)` 的样板代码。
- 模板引用优先使用 `useTemplateRef`，减少字符串 ref 与变量 ref 不一致的问题。
- 组件双向绑定优先使用 `defineModel`，避免重复编写 `modelValue` 和 `update:modelValue` 模板代码。
- 异步组件、懒加载和 `Suspense` 只在确有加载边界时使用，避免为了新特性增加复杂度。

## 平台适配原则

- H5 端允许使用更宽的内容容器和左右分栏。
- 小程序端避免直接访问 `window`、`document`、DOM API。
- 文件下载、复制、分享等能力通过平台封装处理。
- 本地开发联调时，移动端和小程序端不能依赖 `localhost`，需要配置可访问的局域网或测试环境地址。
